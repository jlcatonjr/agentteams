Cliff Notes: Chapter 2: The Problem of Context

Part I: Foundations

A summary of Chapter 2, written to match the text as it describes agentteams 1.1.

Thesis

The chapter argues that the context window is a problem of interpretation before it is a problem of size, and that this constraint creates the demand for every organizational structure the book describes. Attention is finite, so instructions compete for weight. "This is an allocation problem." What erodes first under token pressure is the interpretive frame that tells an agent how to read new material. The chapter concludes that the team's architecture answers the context constraint the way market institutions answer the knowledge problem, and that "Every design decision in the chapters that follow can be traced to this foundation."

What the chapter covers

The first section describes the long-short-term memory problem. As a session grows, an agent loses track of its earliest instructions. Project conventions, the authority hierarchy and constitutional constraints sit at the top of the context but lose effective weight as recent conversation accumulates. An orchestrator that routes well in a short session may later conflate domain agents, skip security checks or run workflow steps out of order, even though the instructions are still present. The chapter insists the problem survives larger windows. Self-attention, after Vaswani et al. (2017), spreads finite weight across every token, so the agent must still prioritize. Miller (1956) on working memory supplies the human parallel, and Clark (2016) supports the claim that interpretation actively reorganizes what receives priority.

The same property has a darker side. Nothing distinguishes documentation an agent should follow from a file it was merely asked to examine, since both arrive as text through the same channel. Content can therefore be composed to redirect the agent reading it. The chapter treats the productive mechanism and the vulnerability as one mechanism, which is why the response "has to be a rule about what counts as an instruction", a subject it assigns to Chapter 7.

The second section applies Hayek. "Each agent in a multi-agent team is a man on the spot for its domain." The bibliography manager, the voice-style agent and the LaTeX specialist each hold knowledge the others lack, and the context window is what makes each agent local. Knowledge proxies answer the problem as prices do, by conveying enough to act on. In Hayek's example the users of tin need to know only that some of the tin they used to consume is now more profitably employed elsewhere, "and that in consequence they must economize tin" (Hayek 1945, 526). Navigation documents, chapter outlines and stage reports are the agent equivalents. A proxy that is too compressed loses essential information, and one too detailed consumes the context it was meant to save.

Proxies are not self-interpreting. Following Hayek (1937), the chapter holds that "The interpretive frame is what converts data into knowledge". For agents the frame is formed by project instructions, the authority hierarchy, voice samples, constitutional rules and agent files. Of those frame documents the chapter says "These documents are not knowledge proxies." The distinction is functional, yet it explains why degradation is systematic. Section 2.3 argues, with Butos and McQuade (2002) and O'Driscoll and Rizzo (1985), that some project knowledge is tacit, situational or generated by investigation itself, so bigger windows are like a larger desk for the central planner. "The desk was never the binding constraint." Because each agent's output changes the environment its successors read, agents must treat their outputs as signals.

The third section describes the degradation curve, which is stable early, then gradually worse, then sharply worse past a threshold, ending in output that is locally coherent but globally inconsistent. Because the pattern is predictable, it can be designed around. The fourth section builds the communication system. "Proxy status is relational, not intrinsic." A report read as a complete inventory invites inferences from its silences that it cannot support. Modular decomposition, credited to the Unix philosophy and to a suggestion from Chris Cowden, keeps each agent loading only its own file plus project instructions, and moving long procedures into scripts saves context. The living document policy guards against temporal degradation, while structural inadequacy of a proxy needs redesign. Good proxies are judged by compression efficiency and interpretive clarity. The chapter ends by bridging to capital theory, since proxies require investment, depreciate and depend on complements.

Key concepts and mechanisms

  • Scarcity of interpretive attention. Finite attention spread across a growing context, which must be economized.
  • Interpretive frame. The instructions, hierarchy, rules and agent files that tell an agent how to read new data.
  • Knowledge proxy. A compressed signal, such as a navigation file or stage report, that guides action without full detail.
  • Frame and proxy distinction. Agent files are frame components, while navigation files, stage reports, change logs and chapter briefs are proxies.
  • Degradation curve. Stable, then gradual, then sharp decline in performance as context fills.
  • Relational proxy status. A document is a proxy only when read as a compressed signal, so its absences index compression rather than absence.
  • Modular decomposition. Small specialized files and referenced scripts in place of a monolithic instructions file.
  • Temporal and structural degradation. Stale details versus an inadequate proxy design.

Theoretical frames

Hayek (1945) supplies the man on the spot and the price system as a communication system for knowledge proxies. Hayek (1937) supplies the claim that compatible expectations are an empirical condition that depends on a shared interpretive frame. Butos and McQuade (2002) and O'Driscoll and Rizzo (1985) support the argument that relevant knowledge resists centralization. Vaswani et al. (2017) grounds the allocation problem in self-attention, Miller (1956) supplies working memory, and Clark (2016) supports active interpretation. Nonaka (1994) and Nonaka and Konno (1998) describe proxy creation as externalization and agent files as ba. Klein (2012) and Koppl and Langlois (2001) tie the division of labor to a division of knowledge that needs defined interfaces.

Why it matters

The chapter supplies the scarcity that drives the rest of the book. Specialization, routing tables, navigation documents, scripts and the living document policy all follow from the need to economize interpretive attention. Its frame and proxy distinction gives later chapters a vocabulary for what a maintenance agent protects, and its warning that proxies are relational shapes how downstream agents should read investigation reports. The point that the same mechanism makes agents both productive and vulnerable sets up the security chapter. The closing bridge prepares the capital-theoretic argument of Chapter 3.
